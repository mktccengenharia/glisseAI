## Acceptance Criteria

1. **AC1 — Rate limiting:** `/api/chat` e `/api/search` devem limitar requisições por IP em uma janela de tempo, retornando 429 quando excedido.
2. **AC2 — Controle de acesso:** o app deve exigir uma senha (via `middleware.js` + cookie assinado) antes de liberar acesso a qualquer rota, configurável via variável de ambiente.
3. **AC3 — Busca full-text:** `/api/search` deve usar o índice `tsvector` em português já existente no schema para tolerar buscas por termos parciais/fora de ordem, mantendo fallback ILIKE para comportamento atual.
4. **AC4 — Mensagem de cobertura:** quando a busca não retorna nenhum resultado, a UI deve informar que a cobertura atual é Capítulos 1-3 da CBHPM, evitando a impressão de bug.
5. **AC5 — Feedback do chat:** cada resposta da LLM deve ter botões de "útil" / "não útil"; a escolha é persistida via `/api/feedback` em nova tabela `chat_feedback` (migration SQL fornecida, aplicação manual pelo usuário).
6. **AC6 — Analytics de buscas sem resultado:** buscas sem resultado devem ser logadas em nova tabela `search_events` (migration SQL fornecida), de forma best-effort (não deve quebrar a busca se a tabela ainda não existir).
7. **AC7 — Testes automatizados:** projeto deve ter `vitest` configurado, com testes para lógica pura (validação de input, formatação, parsers existentes) e script `npm test` funcional.
8. **AC8 — CI:** GitHub Actions deve rodar lint, build e test em push/PR para `main`.
9. **AC9 — Sem regressão:** `npm run lint` e `npm run build` continuam passando.

## Dev Notes

Migrations SQL (`chat_feedback`, `search_events`) precisam ser aplicadas manualmente pelo usuário no SQL Editor do Supabase (seções 10 e 11 de `supabase/schema.sql`) — não há `DATABASE_URL`/Supabase CLI disponível nesta sessão para aplicar DDL programaticamente. Features associadas (feedback, analytics) foram escritas para falhar de forma silenciosa/best-effort até a migration ser aplicada, sem quebrar o fluxo principal.

Controle de acesso (AC2) só entra em vigor em produção depois que a variável `SITE_PASSWORD` for configurada no ambiente de deploy (Vercel). Sem ela, o middleware deixa o app aberto — comportamento intencional para não travar ambientes ainda não configurados.
